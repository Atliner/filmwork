# اپ‌های سبک Vizosten | ویزوستن

Android و Windows فقط پوستهٔ کوچکی هستند و سایت زنده را از `https://namdarcompost.ir/#/home` نمایش می‌دهند. محتوا و API داخل اپ کپی نمی‌شوند؛ بنابراین تغییرات سایت بدون نصب مجدد اپ دیده می‌شوند.

با انتخاب موتور پخش بومی، محدودیت پیشین ۱۰ MiB برای APK و EXE برداشته شده است. Workflow اندازهٔ خروجی‌ها را گزارش می‌کند؛ نسخهٔ Windows فقط برای x64 ساخته می‌شود.

## ظاهر و نمایش

در Android محتوای برنامه از محدودهٔ نوار وضعیت، دوربین و نوار پایین فاصله می‌گیرد. صفحهٔ آغازین Android پس از آماده‌شدن صفحه و حداکثر حدود ۳٫۷ ثانیه کنار می‌رود؛ Windows و PWA آن را حدود ۱٫۵ ثانیه نمایش می‌دهند. زمان بارگذاری خود سایت ممکن است بیشتر باشد. برای مشاهدهٔ تغییرات داخل سایت، پوشهٔ frontend و تغییرات backend باید روی هاست منتشر شوند؛ اپ‌ها همچنان سایت زنده را باز می‌کنند. عنوان و نشان سایت با نام ویزوستن نمایش داده می‌شوند. برای به‌روزرسانی ظاهر سایت و نماد مرورگر، همهٔ فایل‌های frontend از جمله favicon.ico و پوشهٔ icons باید در هاست جایگزین شوند. مرورگر ممکن است برای مدتی آیکون قدیمی را در حافظه نگه دارد.

## Android

از `android-actions/setup-android@v4` استفاده کنید و `tools` را به SDK Manager ندهید؛ این پکیج قدیمی حذف شده است و باعث خطای `Failed to find package 'tools'` می‌شود. Workflow این branch تنها `platform-tools` را نصب می‌کند. ساخت APK با Java 17، Gradle 8.9 و shrink/minify فعال انجام می‌شود.

## Windows

Windows با Tauri ساخته می‌شود و از WebView2 خود Windows استفاده می‌کند، نه Chromium/Electron. اگر WebView2 موجود نباشد، installer نصب‌کنندهٔ کوچک آن را هنگام نصب دریافت می‌کند. نوار عنوان و دکمه‌های اصلی از کنترل‌های خود Windows استفاده می‌کنند و در نسخه‌های پشتیبانی‌شده با رنگ تیره هماهنگ می‌شوند؛ نسخهٔ انتشار پنجرهٔ کنسول جداگانه باز نمی‌کند.

## iPhone / iPad

در Safari آدرس سایت را باز کنید، **Share → Add to Home Screen** را بزنید. PWA فقط پوسته را cache می‌کند؛ درخواست‌های API و اطلاعات حساب cache نمی‌شوند.

## هشدار نصب و امضا

APK با debug key قابل نصب ساخته می‌شود اما ناشر را تأیید نمی‌کند؛ EXE نیز فعلاً Authenticode ندارد. ممکن است Android یا Windows هشدار منبع/ناشر ناشناس نشان دهد. برای ناشر تأییدشده باید کلید انتشار Android و گواهی معتبر Windows تهیه شوند. هیچ‌کدام تضمین نمی‌کنند همهٔ آنتی‌ویروس‌ها هیچ‌گاه هشدار ندهند. هشدار اسکن Play Protect را Google کنترل می‌کند و برای حذف آن راه تضمینی در خود اپ وجود ندارد؛ امضای انتشار ثابت، توزیع معتبر و بررسی Google می‌تواند به ایجاد سابقهٔ اعتماد کمک کند. کلید debug ساخته‌شده در هر اجرای مستقل Actions ممکن است متفاوت باشد و آپدیت مستقیم APK قبلی را ناممکن کند.

## پلیر بومی و ترک‌های داخلی

در صفحهٔ پخش از دکمهٔ «پخش با پلیر بومی» استفاده کنید و نشانی مستقیم HTTPS را وارد کنید. در Android موتور LibVLC در خود اپ اجرا می‌شود و دکمه‌های «صدا» و «زیرنویس» فهرست ترک‌های داخلی را نمایش می‌دهند. در Windows موتور mpv به همراه اپ نصب و در پنجرهٔ پخش جداگانه باز می‌شود؛ برای دیدن و انتخاب فهرست ترک‌ها روی نماد صدا یا زیرنویس در نوار پلیر راست‌کلیک کنید. کلیدهای `g` سپس `a` برای فهرست صدا و `g` سپس `s` برای زیرنویس نیز قابل استفاده‌اند. بدون نصب VLC یا mpv جداگانه کار می‌کند.

این حالت بومی هنوز موقعیت پخش و تبلیغات پلیر وب را همگام نمی‌کند؛ پلیر وب در مرورگر و PWA همچنان به قابلیت مرورگر محدود است. برای نمایش دکمهٔ پلیر بومی و نسخهٔ جدید سایت لازم است فایل‌های frontend روی هاست منتشر شوند. زمان پخش، امکان جست‌وجو در ویدیو و وجود نام ترک به فایل، کدک و پاسخ صحیح سرور رسانه (از جمله پشتیبانی Range) بستگی دارند.

برای ساخت Windows به‌صورت محلی ابتدا `apps/desktop/prepare-mpv.ps1` را اجرا کنید. این اسکریپت نسخهٔ رسمی ثابت mpv را دانلود و SHA-256 آن را تأیید می‌کند. فایل‌های اجرایی دریافت‌شده در Git قرار نمی‌گیرند. راهنمای مجوز و منبع mpv همراه بسته است؛ LibVLC با مجوز LGPL عرضه می‌شود و برای توزیع باید تعهدات مجوزها رعایت شوند.

برای ساخت نمونه‌های کوتاه چندترکی با `ffmpeg` و `ffprobe`، `apps/tests/create-player-fixtures.sh` را اجرا کنید. نمونه شامل H.264، دو صدای MP3/AAC و دو زیرنویس متنی است؛ آزمون فایل واقعی و کدک‌های دیگر همچنان ضروری است.
